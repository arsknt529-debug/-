## PHASE 2｜実装設計

### 2-1. システム構成

**基本方針：すべてブラウザ内で完結する静的なページとして作る。** サーバーへの回答送信・DB・ログイン・LINEプロフィール取得はありません。

```
LINE公式アカウント
  └ リッチメニュー（暫定・変更しない）／メッセージ内リンク
        │  ※導線の追加は承認後、LINE側の設定として別途実施
        ▼
LIFF（設定済みなら） or 通常ブラウザ
        ▼
fitness-line-system.vercel.app
  └ /health-lab/*      ← 今回追加するページ（すべてクライアント側で完結）
        ├ 質問・選択肢・結果文言：リポジトリ内のデータ定義ファイル
        ├ 結果生成：ブラウザ内のルールエンジン（確認可能な条件表）
        └ 回答：画面のメモリ上のみ（7日間ギフトのみ端末内 localStorage ※要承認）
  └ 既存の Webhook / API / LIFF ページ ← 変更しない
```

想定技術構成（**既存リポジトリ確認後に確定**）：

- Vercel 上で動いていることから、Next.js（App Router または Pages Router）である可能性が高いと想定しています。既存が Next.js なら同じルーター方式に合わせます。別のフレームワークの場合も、「データ定義＋共通コンポーネント＋ルールエンジン」の構成はそのまま移せます。
- スタイルは既存の方式（Tailwind / CSS Modules など）に合わせ、HEALTH LAB 用のデザイントークンだけを追加します。
- LIFF SDK：LIFF ID が設定されている場合だけ `liff.init()` を行い、LINE内ブラウザでの表示調整（閉じるボタンなど）にのみ使います。`getProfile()` や `getIDToken()` は**呼びません**。LIFF ID 未設定でも通常ブラウザでそのまま動きます。

### 2-3. 4機能の詳細ページ構成

#### ① 骨格・姿勢を知る（`/health-lab/posture`）

- トップ：指示書のコピー、無料・約2〜3分・器具不要、「判定するものではない」旨、Q6・Q7は任意で痛みがあれば中止できる旨
- 質問：指示書の Q1〜Q8 をそのまま実装
- Q6「痛みがある・試せない」または Q7「わからない・試せない」が選ばれた場合：結果に運動・ストレッチの提案を出さず、休息系のギフトと「痛みが続く場合は医療機関へ」の案内に切り替え
- 結果：3段構成（あなたが気づいたこと／身体をもっと知るヒント／今日からできる小さな一歩）を共通結果フォーマットに載せる
- 導線：60秒セルフケア、トレーナーへの質問、希望者向け無料姿勢チェック、他の3コンテンツ（リンク先URLは要確認）

#### ② 健康診断を読み解く（`/health-lab/checkup`）

- 初期実装は **B（数値入力）と C（項目の意味から知る）**。A（撮影）は「準備中」表示のみ
- 6カテゴリー × 14項目のカード
- 数値入力：検査項目／検査値／単位／検査日（任意）／検査票の基準範囲（任意）／健診機関の判定（5択）
- 入力チェック（医学的な判定ではなく**入力ミスの検出のみ**）
  - 数値でない、空欄、マイナス、小数点が2つ以上 → 入力を促す
  - 単位の取り違えが疑われる値（例：HbA1c を % で 56 と入力 → mmol/mol ではないか確認／クレアチニン mg/dL と µmol/L の取り違え）→ 確認を促すだけで、そのまま進むこともできる
  - 確認に使う「入力として起こりうる範囲」は検査の基準値とは別のもので、これも医療監修の対象
- 結果
  - 健診機関の判定が「要再検査」「要精密検査・要受診」の場合、**最上部に「健診機関の指示に従って医療機関を受診してください」を表示**し、その下に項目の意味を表示
  - 01 数字の意味を知る：項目の一般的な説明文のみ。**入力値が高い・低いという判定は表示しない**
  - 02 自分の変化に気づく：同じ項目・同じ単位で検査日つきの値が2件以上入力されたときだけグラフを表示（保存はしないので、その場で入力した分のみ）
  - 03 次の一歩を考える：一般的な生活習慣情報と、医療機関で確認するとよいこと
- 基準値：アプリ独自の基準値は持たない。利用者が入力した「検査票の基準範囲」は本人の入力として表示するだけで、それを使った自動判定はしない

#### ③ 不調のサインを知る（`/health-lab/signals`）

- **公開条件：症状別の安全基準について医療専門職の監修が完了していること。** それまでは機能フラグで非公開（一覧のカードは「準備中」表示）。プレビュー環境でのみ確認可能にする
- 最初に緊急症状の確認（突然の強い胸痛、強い呼吸困難、突然の片側のまひ・言葉の異常）。「ある」なら以降の質問を出さず、119番への電話ボタン（`tel:119`）を表示して終了
- 8カテゴリーの複数選択 → 共通Q1〜Q5 → 選んだ症状ごとに追加質問1〜3問
- 受診目安の判定（仮案。**監修で確定するまで公開しない**）

| 判定 | 条件の例（仮） | 表示 |
|---|---|---|
| 緊急 | 最初の緊急症状チェックで「ある」／むくみ：片側＋急に発生＋痛みや息苦しさあり | 119 案内。セルフチェック中止 |
| 早めの受診をすすめる | Q4「急に悪くなった」／Q3「大きく支障がある」／お腹：出血あり／肩・腰：しびれあり／ストレス・気分で安全上の懸念がある回答 | 結果の最上部に受診・相談窓口の案内を表示し、その下に通常の内容 |
| 相談を考える | Q1「数か月以上前から」かつ Q4「徐々に悪くなっている」 など | 通常の結果に「続く場合は医療機関へ」を強調表示 |
| ふり返り | 上記以外 | 通常の結果「身体からの手紙」 |

- 判定は「どれか1つでも当てはまれば上の段を優先」とし、重い側に倒れる設計にする
- 結果「身体からの手紙」：あなたが気づいたこと／見つめ直したい生活のポイント／今日の小さなギフト／医療機関への相談が必要な場合の案内
- 原因や病名は表示しない。「〇〇の可能性があります」という書き方もしない
- 「早めの受診」判定のときは、通常の健康コンテンツ（動画・7日間など）への導線を目立たせない（誤誘導防止）
- 次のアクション：60秒の健康習慣動画、不調の記録方法、適切な医療相談先、7日後の振り返り（初期は「7日後にもう一度チェックしてみましょう」という案内文のみ。通知はしない）、XCOUNT の健康情報

#### ④ 未来の健康を考える（`/health-lab/future`）

- 指示書の Q1〜Q10 を1問ずつ表示。進捗バー・戻る操作あり
- 各回答を「大切にできている」「見直す余地がある」「対象外」の3つに分ける。「わからない」「答えたくない」は**対象外として扱い、どちらにも数えない**
- 5領域（2問ずつ）について
  - 見直す余地のある回答が1つでもある → 見直す余地がある習慣
  - 大切にできている回答があり、見直す余地の回答がない → 今大切にできている習慣
  - 2問とも対象外 → 表示しない（「この領域は今回はお休み」程度の表現）
- 点数・健康年齢・余命・リスクは表示しない
- 7日間のギフト：5領域の約束から1つを選ぶ（見直す余地のある領域を先頭に並べる）→ 7日カレンダーで「できた日」に印をつける
  - できなかった日を否定する表現は使わない（例：「これまでに3日、自分を大切にする時間がありました」）
  - 記録の保存先は**この端末の localStorage のみ**（要承認）。消去ボタンを用意。LINE 通知・サーバー保存はしない

### 2-5. 質問データの管理方法

質問・選択肢・結果文言は**画面のコードから分離したデータファイル**で管理し、非エンジニアのレビューでも差分を読めるようにします。

```ts
// content/health-lab/posture.ts（例）
export const postureQuestions: Question[] = [
  {
    id: 'q1_sitting',
    text: '長時間座った後、どんな姿勢になりやすいですか？',
    type: 'single',
    options: [
      { id: 'rounded', label: '背中が丸くなりやすい' },
      { id: 'arched',  label: '腰を反らせがち' },
      { id: 'tilted',  label: '左右どちらかに傾きやすい' },
      { id: 'none',    label: '特に気にならない' },
    ],
  },
  // Q6・Q7 は optional: true（「試せない」でスキップ可）
];
```

文言には監修状態を持たせます。

```ts
type Copy = {
  id: string;
  text: string;
  review: { status: 'draft' | 'reviewed'; reviewer?: string; date?: string };
};
```

- 本番ビルド時に、公開対象の機能に `draft` の文言が残っていないかをテストで検査する（「不調のサイン」は全文言 `reviewed` でないと公開フラグを有効にできない）
- 文言一覧を CSV / Markdown に書き出すスクリプトを用意し、監修者に渡せるようにする

### 2-6. 結果生成のロジック

**確認可能なルールベース**です。AI・確率計算・スコアリングは使いません。

```ts
// content/health-lab/posture.rules.ts（例）
export const postureRules: Rule[] = [
  {
    when: { q2_fatigue: ['neck_shoulder'] },
    discovery: 'posture.discovery.neck_shoulder',   // 「首・肩まわりへの負担が気になっているようです。」
    understanding: 'posture.understanding.same_posture',
    gift: 'posture.gift.stand_up',
  },
  {
    when: { q6_arms: ['pain'] },
    suppress: ['exercise_gifts'],                   // 痛みがある場合は運動提案を出さない
    gift: 'posture.gift.rest',
    safety: 'common.safety.pain_persist',
  },
];
```

- 条件は「どの質問でどの選択肢を選んだか」のみ。回答から直接言えることだけを結果に出す
- 複数ルールが当てはまる場合の優先順位（安全 ＞ 本人が一番知りたいこと（Q8）＞ その他）を表で定義
- ルールと文言の対応表をそのままテストケースにする（全選択肢の組み合わせで結果が空にならない・禁止語を含まないことを検証）
- 禁止語チェック：「猫背です」「反り腰です」「骨盤がゆがんで」「〇〇病」「リスク」「健康年齢」などを結果文言に含まないことをテストで確認

| P4 | 緊急症状の案内（119） |
| P5 | 7日間のギフト（カレンダー）※操作可 |

デザインの考え方：

- 色：**XCOUNT ロゴの4色**をブランドカラーとして採用し、4つのコンテンツに1色ずつ割り当てています

  | ロゴ色 | 割り当て | 文字・白文字ボタン用（4.5:1 以上） |
  |---|---|---|
  | 青 `#306CB2` | CARD 01 骨格・姿勢 | `#306CB2`（そのまま） |
  | 緑 `#43964E` | CARD 02 健康診断、メインボタン、小さなギフト | `#2E7A3C` |
  | ピンク `#C74D88` | CARD 03 不調のサイン | `#B0417A` |
  | 黒 `#211916` | CARD 04 未来の健康、本文の文字色 | `#211916` |

  ベースは Background `#FAF8F4`、Surface `#FFFFFF`、Beige `#EFE6D8`、Muted `#6B6560`。赤 `#B3261E` は**緊急・安全の案内だけ**に使います。ロゴの原色（緑・ピンク）は白地での文字コントラストが足りないため、線・面・アイコンの装飾にだけ使い、文字には濃くした色を使います。一覧の最上部とヘッダーのロゴマークで4色をブランドの印として見せています
- 書体：見出しは丸みのあるやさしい **Zen Maru Gothic**、本文は読みやすさに配慮した UD 書体 **BIZ UDPゴシック**。アプリではフォントをパッケージ（@fontsource）から自前で配信し、外部のフォントサーバーには通信しません
- 写真：XCOUNT Fitness の実店舗・スタッフの写真を使用（ピクトグラム・イラストは使わない）。`health-lab/scripts/build-images.py` が、シーンごとに元写真の使う部分を切り出し、色味（彩度・明るさ・温かみ）をそろえて 16:10 の WebP を自動生成する。元写真を差し替え・追加したら再実行するだけで全画像が作り直される
- 人物写真の扱い：このリポジトリは公開設定のため、スタッフ写真はリポジトリに含めていない（`--include-people` を付けたときだけ使用）。リポジトリ版の「未来の健康」は店舗写真で代用。共有用プレビュー・デザイン案ではスタッフ写真を使用
- 救急車の専用ページは廃止（依頼による）。不調のサインのトップに「急を要する症状があるときは119番へ」を1行で常に表示し、症状別の質問で「息苦しさがある」を選んだ場合はその場と結果の最上部に119番の案内を表示
- 「今日の小さなギフト」は4機能共通で、塗りのセージグリーンのカードとして結果画面の中心に置きます
- 写真・筋肉表現・強い原色・装飾的なアニメーションは使っていません。姿勢トップのイラストは仮の線画です
