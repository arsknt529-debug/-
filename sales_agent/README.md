# Sales Agent (アサイーボウル 卸し先開拓)

美容・フィットネス業界向けに、アサイーボウルの卸し導入を提案する営業活動を
半自動化するためのワークスペース。Claude Code(このリポジトリにアタッチされた
Gmail連携付きのセッション)が実行役を担う想定。

## できること / できないこと

- **できる**: 候補となる卸し先(健康・美容意識の高いサロン等)をWeb検索でリサーチし、
  `prospects.csv` に蓄積。各候補ごとに `product.md` の内容をもとにパーソナライズした
  提案メールの**下書き**を Gmail に作成する。
- **できない**: メールの自動送信。接続されている Gmail 連携ツールには下書き作成
  (`create_draft` / `update_draft`)しかなく、送信用のツールは存在しない。
  これは意図した安全設計でもある — 未承諾の営業メール(特定電子メール法の対象)を
  人の確認なしに送りつけるのはリスクが高いため、**最終送信は必ず人が Gmail 上で
  内容を確認してから行う**。

## セットアップ

```bash
cp sales_agent/product.md.example sales_agent/product.md
# product.md を編集して、商品概要・卸値・ターゲット業態・エリア・送り主情報などを記入する
```

`sales_agent/product.md` は `.gitignore` 対象(卸値など機密情報を含むため)。

**注意**: Routine(定期実行)で使い捨てコンテナが毎回リポジトリを新規クローンする
運用にする場合、`.gitignore` 対象のファイルは新しいコンテナに存在しない。
このリポジトリは非公開(private)なので、定期自動実行させたい場合は
`product.md` も普通にコミットしてしまう方が安全に運用できる。手元でしか
使わない/毎回自分でコピペする運用にするなら、現状どおり `.gitignore` のままでよい。

## 候補リスト (`prospects.csv`)

列の意味:

| 列 | 説明 |
|---|---|
| name | 店舗・会社名 |
| category | 業態(エステ/ジム/ヨガスタジオ など) |
| area | 所在エリア |
| website | 公式サイトURL |
| contact_email | 問い合わせ先メールアドレス(公開情報から取得できた場合のみ) |
| status | `new` (未着手) / `drafted` (下書き作成済み) / `contacted` (送信済み・人が手動更新) / `skip` (対象外と判断) |
| source | どこで見つけたか(検索クエリ・サイト名など) |
| added_date | 追加日 |
| notes | 補足メモ |

このファイルはリポジトリにコミットして、Claude Code のセッションが
使い捨てコンテナで再実行されても候補リストと進捗(status)が引き継がれるようにする。

## 実行フロー(エージェントが行うこと)

1. `product.md` のターゲット業態・エリアをもとに、Web検索で新規候補を探す
2. `prospects.csv` に既にある候補と重複しないか確認し、新規のみ追加(`status=new`)
3. `status=new` の候補について、`product.md` の内容を踏まえたパーソナライズ提案メールを
   Gmail の下書きとして作成し、`status` を `drafted` に更新
4. 変更した `prospects.csv` をコミット・プッシュして状態を保存
5. 実際に送信するかどうか・送信後の `status=contacted` への更新は人が行う

## 定期実行(Routine)にする場合

Claude Code Remote の Routine(`create_trigger`)で、このリポジトリ + Gmail 連携を
使って上記フローを定期実行できる。候補の使い切りやスパム化を避けるため、
1回の実行で新規に連絡する件数には上限を設けることを推奨。
